# 官网内容与发布维护手册

适用独立仓库 `ops-harness-website`。文档编辑不读取或修改 DSH_HOME、Profile、用户会话或 Desktop 更新配置。

## 启用管理员模式

管理员密码没有默认值。启动前通过环境变量提供密码，最长 256 个字符：仅监听 loopback、使用 loopback HTTP 地址的开发服务最短为 6 位，生产服务及其他监听配置最短为 16 位。所有环境均执行登录鉴权。已有服务必须停止后重新启动，才能读取新凭据。macOS / zsh 下可以这样输入，密码不会进入 shell 历史或回显：

```sh
read -rs 'DSH_OPS_WEBSITE_ADMIN_PASSWORD?请输入管理员密码（至少 16 个字符）：'
export DSH_OPS_WEBSITE_ADMIN_PASSWORD
pnpm dev
```

生产环境先执行 `pnpm build`，再执行 `pnpm start`；环境由部署服务或凭据管理器注入，不写入 Git、JSON 配置或普通日志。

环境变量只对当前 shell 及其启动的服务生效；新开终端或由其他方式启动时，需要重新注入密码。

打开 `/admin` 登录。登录会话最长 8 小时，闲置 30 分钟、退出或服务重启后失效。认证前只显示登录页，不加载编辑器和其他管理工作区。更换环境中的密码并重启可轮换凭据。未配置密码时页面显示配置说明，公开阅读仍可使用。

公网生产部署在 HTTPS 网关后运行；受控内网也可显式配置 HTTP IP / 域名直连，见 [简明部署手册](website-deployment-ubuntu-debian.md)。`config/website.json` 的 `websiteUrl` 必须与浏览器访问的协议、地址、端口一致；管理接口校验 Host 和 Origin，不要混用 localhost、127.0.0.1 或不同域名。内网 HTTP 仍要求 16–256 位管理员密码；HTTP Cookie 保留 HttpOnly / SameSite，HTTPS 时额外启用 Secure。

## 日常编辑

1. 在“文档编辑”左侧列表选择已有文档，可按名称或目录查找。该页面只修改 Markdown 正文；文档名称、简介、目录与顺序统一在“目录与文档管理”维护。
2. 工具栏可切换 Markdown 分屏、即时渲染或所见即所得。“阅读预览”使用公开页面的同一渲染器。
3. 点击“保存并发布”；读者重新打开或切换到该章即可看到更新。未保存草稿仅在当前页面内存中，支持下载和离开提醒，不自动发布或存入 localStorage。切换管理功能或文档前也会提示未保存修改。
4. “历史版本”可查看旧内容，选择“恢复此版本正文”只恢复 Markdown 正文，保留当前名称、简介和目录设置。当前版本仍会留在历史记录中。

两个管理员修改同一章时，后保存者会收到冲突提示。先下载自己的草稿，再读取最新版本并人工合并，不强行覆盖。登录过期时当前草稿保留在页面内，可下载或重新登录后继续处理。

## 目录与文档管理

独立管理页保持“目录 → 文档”两级结构，按目录展示文档列表，不使用树状菜单；每行直接显示操作按钮。

- “新建目录”创建空目录。每个目录可重命名、上移、下移和删除；先移出所有文档（含回收站中的文档），才能删除空目录。
- 在目标目录点击“新建文档”，填写名称、简介和文档标识。标识自动生成，也可在创建前修改；创建后保存初始正文并进入编辑页继续编写，链接保持不变。
- 文档行的“名称与简介”维护元信息；“编辑正文”进入独立编辑页。“移动”、上下排序和隐藏/显示操作完成即保存，阅读页、搜索顺序和前后章导航同步更新。
- “移至回收站”停止公开文档，保留内容、历史和原目录位置；切换管理页的“回收站”后可恢复。没有永久删除文档的操作。
- 隐藏只影响导航，直接链接仍可访问；停止公开请移至回收站。恢复文档保留原来的目录可见性。
- 目录和文档使用稳定标识，同名目录仍能准确定位新建文档。保存检查 revision；冲突时先取消对话框，再读取最新目录后重试。
- 操作按钮可用 Tab 导航、Enter / 空格触发；Escape 取消对话框并返回触发位置。回收恢复导致原操作行消失时，焦点回到管理页搜索框。

## 图片与文字混排

在正文编辑器中使用上传按钮、粘贴剪贴板图片或拖入本地图片，上传成功后在光标位置插入标准 Markdown。图片前后可以编写段落、列表、表格和说明文字，例如：

```md
完成配置后，打开工具市场：

![工具市场配置界面](/assets/product/tools.jpg)

点击“添加”，检查工具是否可用。
```

也可点击“从图片库插入”，填写图片说明并选用已上传图片。独立“图片库”页支持上传、按名称查找、查看原图、复制 Markdown 地址。每张最多 10 MiB、最大边长 16000 像素且总像素不超过 4000 万，最多 4000 张；重复图片按内容去重。大图建议先压缩。当前图片库不提供删除，避免破坏已发布正文及历史版本的引用。

上传成功不等于章节已发布；点击“保存并发布”才会更新阅读页。取消上传保留已完成的图片，未完成字节自动清理。支持三种编辑模式，公开页始终使用同一个安全 Markdown 渲染器。

## 软件发布与 Changelog

1. “发布包” → “新建发布”，选择与安装包同一次打包生成的 `latest.yml`（Windows）或 `latest-mac.yml`（macOS）。页面自动展示版本、平台、文件名、预期 SHA-512 及可选的大小（未提供时显示“上传后读取大小”）。描述文件上限 32 KiB，不需要上传 builder 配置或调试文件、`.blockmap`。
2. 填写版本标题及逐行更新说明，保存草稿。版本和校验清单由服务端解析并锁定；如选错描述文件，保存前可重新选择，保存后需新建草稿。同版本多平台共享说明，页面会自动沿用已有平台的标题和说明。
3. 上传清单中的原始安装包，不要重命名。Windows 主文件为 `.exe`，macOS 主文件为 `arm64.zip`；主文件必需，清单中的其他软件包可选。每个平台最多 8 个文件，每个文件最多 2 GiB。网页不接受描述文件中没有列出的附件。
4. 服务端将收到的 SHA-512 与描述文件比对；若描述文件提供了 `size`，也比对大小，否则记录实际字节数，通过才显示“校验通过”。失败文件不会进入草稿，已成功上传的文件保留。出现校验失败时重新选择同一次打包的原始文件；不要修改 YAML 中的哈希来绕过校验。取消或连接中断会清理未完成的临时文件。
5. 核对文件清单和更新说明后点击“核对并发布”，再次确认。发布事务重新读取文件，与描述文件的基准比对，通过才开放下载与自动更新。网页默认立即发布，灰度 100%。客户端读取的 `latest.yml` 继续由官网根据已验证的发布目录动态生成。
6. 旧草稿需要先补充对应版本和平台的描述文件；服务端也会检查已有文件的实际内容。遇到不匹配的旧文件可移除后重传。已发布版本仍可修改标题、changelog、上下架状态，安装包不可覆盖。
7. 草稿及原始描述文件内容一起保存在发布目录中，可移至 `releaseDirectory/.trash`；清理已发布草稿不影响公开版本。发布失败时先刷新列表检查结果。

上传只接收和校验文件，不运行或解压软件包，不代替数字签名和目标平台安装测试。描述文件也应来自可信的原始构建；如果坏包和描述文件同时被替换，哈希一致不能证明来源可信。大于 2 GiB 或未列入清单的附件仍可使用原有 CLI；CLI 会计算本地文件哈希，不要求此描述文件。详见 [官网 README](../../README.md) 与 [ADR 0017](../adr/0017-manifest-first-release-upload.md)。

## 知识库与技能维护

在 `/admin` 打开“知识库”。上方技能区维护可复用的技能文件，下方逐个维护知识库及其引用；保存后即更新官网目录，“上架”控制知识库是否出现在公开目录。

1. 在技能区选择一个或多个 `.zip` / `.md` 文件上传，每个最多 5 MiB，目录最多保留 100 个技能。每份文件须包含有效的 `SKILL.md` frontmatter，其中 `name` 是技能的稳定标识。上传同名技能会替换该技能的文件，所有已有引用继续使用这个名称；上传不同名称会新增技能。多文件上传后逐项核对结果，成功项已保存，失败项需修正后重传。
2. 新建或选择一个知识库，填写租户、知识库 ID、描述等信息，在技能引用区选择已上传技能，可不选或选择多个。同一技能可被不同知识库复用；选择后保存知识库才会更新其引用。
3. 在检索工作流区按行填写“名称 / 值”。名称是工作流映射的 key，值是对应 value；可新增、删除行，最多 50 行，也可全部移除。名称最多 80 字符，值最多 256 字符，去除首尾空白后都不能为空，名称不能重复。示例：名称 `query_card_data`，值 `wf-card-data`；名称需与消费该配置的产品端约定一致。
4. 保存前核对技能引用和工作流。上传技能与保存知识库是独立操作；切换条目或管理页时按未保存提示处理草稿。出现 revision 冲突时先保留当前输入，再读取最新目录并合并，避免覆盖其他管理员的修改。
5. 移除技能前，先从引用它的每个知识库中取消选择并保存，包括下架知识库。仍有引用时服务端返回 `SKILL_IN_USE`，不会连带修改知识库。删除知识库不会删除其引用过的技能；移除或替换技能也不会清理磁盘上的历史哈希文件。

技能文件在上传后即可通过公开接口下载，未被知识库引用的技能也属于公开技能列表。不要上传凭据或需要保密的内容。上传只校验文件结构，不执行技能、不验证工作流是否可调用，实际消费规则由产品端负责。

本版本公开目录为 `schemaVersion: 2`：顶层 `skills` 提供技能列表，条目 `skill_names` 指定引用，`knowledge_retrieve_workflow_id` 提供自定义名称到值的映射。上线前先与产品端维护者确认 v2 读取、指定技能下载、多个知识库共用技能时的安装与解除绑定行为；官网改造不代表产品端接入已完成。接口与文件校验细则见 [README 知识库说明](../../README.md#知识库元数据指标知识库) 和 [ADR 0018](../adr/0018-metric-knowledge-catalog.md)。

### 知识库目录升级与恢复

部署前完整备份 `contentDirectory/knowledge/`，包括 `catalog.json`、`skills/` 和 `.trash/`，并记录当前运行版本。新版本读取 v1 目录时自动将顶层共用技能迁入 `skills`；知识库未声明 `skill_names` 时默认引用该技能，没有顶层技能时默认空引用。显式已有的 `skill_names`（包括 `[]`）保留，旧条目级技能继续忽略。原有工作流值保留，旧拼写 `quer_card_data` 在 v1 迁移时改成 `query_card_data`。

读取迁移不修改原文件，首次成功保存、上传或移除操作前，会先把原 v1 `catalog.json` 复制到 `knowledge/.trash/catalog-<时间戳>.json`，再将目录写为 v2；首次操作是新建知识库或新增技能时也会备份。升级后重新读取管理员目录，核对条目数、技能名与引用、工作流和上架状态，再进行修改；不要继续提交旧页面持有的 revision。公开接口随新服务直接返回 v2，无需等目录文件首次写入。

需要回滚时先停止写入和服务，再恢复相互匹配的整个 `knowledge/` 备份及对应服务版本。旧服务不能直接读取 v2 目录；不能只回退代码，也不能仅把文件中的 `schemaVersion` 改回 1。恢复后重新读取目录，核对技能下载内容与哈希，再恢复运营维护。

## Markdown 格式

每章一个文件，文件名与 frontmatter 中的 `id` 一致。例如 `content/guide/getting-started.md`：

````md
---
id: getting-started
title: 开始使用
group: 开始使用
order: 10
summary: 安装并完成第一项工作。
archived: false
---

## 第一步

编写具体操作，并说明如何确认成功。

```text
这里是读者可以复制的示例。
```
````

必填字段是 `id`、`title`、`group`、`order`、`summary`（可空）；`archived` 默认 false。约束：

- ID 以小写字母开头，仅用小写字母、数字和分隔用连字符，最长 64 字符；与文件名一致。
- 标题最多 100 字符，分组 60 字符，简介 500 字符；排序为 0–100000 整数，建议间隔 10。
- 每章最多 128 KiB，共最多 200 章（含回收站）。支持 UTF-8 BOM、LF / CRLF。
- 正文支持标准 Markdown、表格、链接和代码块；不执行 HTML、脚本或复杂图表扩展。
- 图片支持本站静态 `/assets/` 和上传后的 `/media/<sha256>.<ext>` 地址，格式为 JPEG、PNG、WebP。远端图片、SVG 和 data URL 不会渲染。上传图片无需修改代码或重新构建。

更新操作说明时核对实际产品界面与插件 README，不把待接入功能写成已可用。截图重新采集要求见 [官网 README](../../README.md)。

## 存储与发布

`config/website.json` 统一配置服务地址、发布目录、文档目录与管理员密码环境变量名称。用 `DSH_OPS_WEBSITE_CONFIG` 指向另一份完整配置；`contentDirectory` 和 `releaseDirectory` 相对配置文件所在目录解析，默认分别为 `../.runtime/website-content` 和 `../.runtime/website-releases`，`adminPasswordEnv` 为 `DSH_OPS_WEBSITE_ADMIN_PASSWORD`。配置本身不含密码，变更后需重启服务。

旧的两份配置需合并后使用，官网不再分别读取 `DSH_OPS_RELEASE_CONFIG` 和 `DSH_OPS_WEBSITE_CONTENT_CONFIG`。迁移时保持两个目录指向原有数据，替换配置环境变量并重启；具体步骤见 [README 配置说明](../../README.md#配置)。

```text
content/guide/*.md             # Git 发布基线
content/guide/navigation.json  # 同步后的目录配置
content/media/                # 同步后的图片和 index.json
.runtime/website-content/guide/current/    # 在线发布版本，优先于同 ID 基线
.runtime/website-content/guide/history/    # 被替换的版本，按章节和 revision 分文件
.runtime/website-content/guide/navigation.json # 在线目录配置
.runtime/website-content/media/            # 上传图片与 index.json
.runtime/website-content/knowledge/catalog.json  # 指标知识库元数据目录
.runtime/website-content/knowledge/skills/       # 按内容哈希保存的技能文件
.runtime/website-content/knowledge/.trash/       # 覆盖或删除前的目录副本
.runtime/website-releases/.admin-drafts/    # 发布草稿和上传文件
.runtime/website-releases/archive/          # 不可变发布文件
.runtime/website-releases/catalog.json      # 版本说明、策略和下载清单
.runtime/website-releases/.trash/            # 已移除的草稿与文件
```

开发服务逐次读取源文件，无在线覆盖时直接修改 Markdown 即可生效；生产构建将文档、目录和图片分别复制到 `dist/content/guide/` 与 `dist/content/media/`。部署时持久保留并备份整个 `contentDirectory` 和 `releaseDirectory`，新代码不会覆盖在线编辑。

某章存在在线版本时，后续 Git 基线变动不会自动替换它。管理员可“下载已保存的 Markdown”，或使用下述同步功能写回源码；日常保存不自动反向同步。需要重新跟随 Git 时，先备份并核对两个版本、停止服务，将对应 `current/<id>.md` 移到内容目录外的备份处，重启后验证。不要直接删除在线目录或历史。

写入使用独占锁和原子替换。异常退出留下 `guide/.write-lock` 时，先确认没有其他写入进程、备份数据，再处理残留锁；服务不擅自解锁。内容损坏时明确报错并保留原文件，不用基线静默覆盖人工修改。

`knowledge/` 只存在于运行目录，不参与“同步到 content”、不进 Git，也没有 Git 基线可回退，因此必须整目录备份：`catalog.json` 是指标知识库元数据的唯一权威副本，`skills/<sha256>.<zip|md>` 是端侧下载的技能文件字节，两者必须一起备份和一起恢复，否则条目会指向缺失的哈希，公开下载接口报 404。覆盖或删除条目前服务会把旧目录复制到 `knowledge/.trash/catalog-<时间戳>.json`，可用于人工回滚；这些副本不会自动清理，容量规划时按条目数和技能文件累积估算，删除条目不回收 `skills/` 中的文件。异常退出留下 `knowledge/.knowledge-lock` 时，同样先确认没有活动写入进程并备份，再由维护人员处理。`catalog.json` 损坏时接口返回 503 并保留原文件，不要用空目录覆盖——先从备份或 `.trash/` 副本恢复并核对 `revision` 变化。

## 同步到 content 并提交主仓

1. 在管理员页点击“同步到 content”。当前文档如有未保存修改，会先执行保存；发布包页面的未保存修改需先处理。
2. 核对确认框里的文件清单和“新增 / 覆盖”标记，然后点击“确认同步”。同步文档到 `content/guide/*.md`、目录到 `content/guide/navigation.json`、图片及索引到 `content/media/`。图片仍引用 `/media/<sha256>.<ext>`，无需改写 Markdown 链接。
3. 完成后检查源码变更，运行 `pnpm check` 和 `pnpm build`，再按团队流程提交到主仓。同步不会代替 Git 提交，也不会改变其他源码、发布包或在线历史。

服务必须从包含 `content` 的官网项目根目录启动，并有写权限；只部署 dist 的服务不能写回不存在的源码目录。同步目标不能由浏览器指定。原文件及新文件保存在 `contentDirectory/sync-backups/<id>/old`、`new`，`manifest.json` 记录文件哈希和状态；完成后在线覆盖仍保留。

确认后如有人又编辑在线文档、图片或目标文件，服务器返回冲突，取消后重新预览即可。遇到进程中断或回滚不完整时，同步会停止，避免继续覆盖：停止同步写入，确认没有活动进程，备份运行和源码目录；对照 `content-sync-review.json` 指向的备份及 `manifest.json`，人工恢复或补全清单中的文件；核对无误后再移走检查标记和残留 `.content-sync-lock`。不要直接删除备份，也不要将 `.runtime` 纳入 Git。

## 登录防护与部署

应用在读取登录 JSON 前计数：单连接来源 5 分钟最多 5 次，全站 5 分钟最多 50 次尝试，最多 2 个并行登录请求。登录请求上限 2 KiB、接收超时 5 秒；触发限流返回 429 与 Retry-After。伪造 X-Forwarded-For 等请求头不能绕过这些限制。密码错误、无会话、跨站来源或缺少 CSRF 的写入均会被拒绝。

公网部署继续由 HTTPS 网关承担 TLS，并在网关配置真实来源的请求速率、连接数、请求大小和超时限制。应用只使用实际连接地址，不解析任意代理头；多个访问者经同一网关连接时会共享应用侧来源限额。再次登录使该浏览器的旧会话失效；不要在配置文件、日志或网页里保存密码。详细决策见 [ADR 0015](../adr/0015-admin-workspace-and-content-sync.md)。

## 维护验证

在仓库根目录运行 `pnpm check` 和 `pnpm build`。检查变更章节的目录、链接、表格、代码复制和图片；编辑器升级还需验收三种模式、保存/刷新、历史恢复、回收站、登录退出以及生产环境的本地资源加载。

当前采用 Vditor 4.0.0，选型比较、许可证与引入边界见 [ADR 0012](../adr/0012-markdown-guide-administration.md)。

新增发布、图片和目录写入分别使用发布锁、图片锁、章节锁；异常断电后留下的锁或临时文件应先确认没有活动写入进程、备份，再由维护人员处理。服务不会擅自解锁。生产网关设置至少 2 GiB 的单次请求容量和相应上传超时；应用上传总时限 30 分钟、空闲时限 60 秒，JSON 请求时限 15 秒。上线前请检查持久化磁盘空间。
