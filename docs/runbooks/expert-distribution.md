# 专家分发运维

2026-09-26。管理员在 `/admin` 的“专家分发”里导入、编辑、发布专家，维护自定义工具库与内置专家的常用场景；设计与取舍见
[ADR 0022](../adr/0022-expert-distribution.md) 与 [ADR 0023](../adr/0023-expert-scenarios.md)，产品侧见产品仓库 ADR 0026、0027 与 `docs/runbooks/cloud-experts.md`。

## 日常操作

1. **导入**：创建者在工作助手“我的专家”导出 `*.expert.zip` 并发给管理员。后台“导入专家包”后先看预览：目标（新建，或按
   “导出人工号 + 本机专家 ID”自动选中的已有专家）、变化摘要、自定义工具（新增 / 直接复用 / 同名但配置不同）、知识库状态与警告。
   同名不同配置的工具必须选择“更新已有工具”（会影响所有引用它的已发布专家）或“改名后新增”（模型看到的工具名随之改变）才能导入。
2. **可见范围与发布**：分发设置保存即生效（上架 / 下架、全员或指定工号、是否允许克隆）；负责人始终可见。内容改动需要“发布新版本”，
   使用者下次同步收到（打开专家页即同步，另有每 30 分钟的系统任务）。
3. **自定义工具库**：“自定义工具”页签可改名称、说明、服务地址或命令与参数、调用超时、凭据项的名称与获取说明；保存即对所有引用它的专家生效，
   保存前会提示将影响几位已发布专家。凭据项的值从不在官网保存。被任何专家（草稿或已发布版本）引用的工具不能删除。
4. **下架与删除**：下架后使用者下次同步收回该专家（运行中的对话到重启前不受影响，克隆副本保留）。删除专家会把记录移入 `.trash/`。
5. **常用场景**：专家表单的“常用场景”逐条添加、编辑、调整顺序与删除（每位专家最多 8 个；名称 ≤16 字，简介 ≤40 字，提问模板 ≤300 字、
   最多 3 处 `【】`，可选工作模式与图标；不选图标时按工作模式或专家图标自动配）。场景跟随专家版本，保存草稿后“发布新版本”才到达使用者。旧版工作助手不显示场景，把场景名称显示为 Prompt 建议。
   正在编辑的场景行要先“保存场景”或取消，才能保存草稿、发布或上传、移除技能。导入带场景的专家包时，包里由场景名称生成的 Prompt 建议不保存
   （更新已有专家时保留它原有的 Prompt 建议），删光场景后不会留下过期的名称。
6. **内置专家场景**：“内置专家场景”页签列出随安装包发布的五位专家。保存草稿不影响任何人；“发布”后这份列表**整体替换**该专家随产品发布的场景
   （发布空列表即隐藏），所有同事（包括未识别工号的使用者）下次同步时生效；没有可发布的改动时“发布”不可用。“恢复为随产品发布”撤下覆盖并丢弃草稿，
   只在已发布覆盖或已保存草稿时出现。

内置工具清单与当前客户端实际装配的九项工具对齐（契约 0.2.5）：

| 官网显示名 | 稳定工具 ID |
| --- | --- |
| 网页抓取 | `webfetch` |
| 浏览器操作 | `browser` |
| 多媒体创作 | `multimedia` |
| 指标查询 | `metric-query` |
| 数据资产查询 | `data-asset-query` |
| DataAgent连接器 | `data-agent-tool` |
| DataOps连接器 | `dataops-tool` |
| WeLink | `welink` |
| 运营平台认证 | `operations-platform-auth` |

可按专家需要设为“必需”；保存草稿并发布后，该引用随专家下发，导入预览也使用同一标识。下发的内置工具引用只有 `toolId` 与 `required`，不携带显示名；工作助手按稳定 ID 查找并添加工具，显示名沿用客户端本地目录。官网只维护引用，多媒体创作等工具的实际能力取决于客户端插件；当前公开产品的多媒体实现为固定示例图 demo，官网补项不会接入新的生图服务。

Shell、文件、目标、待办、子代理仍在“基础能力”中单独提供。自定义工具沿用独立工具库；已停止装配的 `web-search`（中文全网搜索）、`xiaoluban`（小鲁班）以及运行环境等设置服务不加入内置工具清单。此对齐不修改客户端实现，也不改变客户端现有的专家导出能力。

## 升级顺序

- **契约 0.2.0（2026-10-06，技能共用规则与放宽的上限）：先发布新版工作助手，再升级官网。** 旧官网仍按旧上限拒收大包，新版工作助手
  照常工作；官网升级后，导入预览会对旧版工作助手装不下的技能或专家给出警告（例如“技能「x」超出旧版工作助手的能力：压缩后 6 MB
  （旧版上限 5 MB）”或“这位专家有 21 个技能，超出旧版工作助手的上限 20 个”）。可以照常导入发布；使用旧版的同事只是收不到这一位，
  升级后下次同步即可收到。

- **官网先于会导出常用场景的新版工作助手部署。** 专家包格式是严格的：契约 0.1.0 的旧官网会以 `INVALID_EXPERT_PACKAGE`（未知字段 `scenarios`）
  拒绝带常用场景的专家包。先把官网升级到契约 0.1.1（本版本）并重启，再发布新版工作助手；没有场景的专家包不带这个字段，新旧官网都能导入。
- 目录方向可以任意顺序升级：旧版工作助手请求目录时不带 `X-Ops-Expert-Features: scenarios`，收不到新字段。

## 存储与备份

内容目录下的 `experts/`：

| 路径 | 内容 |
| --- | --- |
| `catalog.json` | 全部专家的草稿、分发设置、已发布版本指针与导入来源 |
| `tools.json` | 自定义工具库（可移植定义、凭据项名称与获取说明、内容摘要版本号） |
| `builtin-scenarios.json` | 内置专家常用场景的草稿与已发布覆盖（只含有过改动的专家；恢复为随产品发布即删除该专家的条目） |
| `versions/<专家 ID>/<版本>.json` | 发布快照，不可覆盖 |
| `skills/<sha256>.<zip\|md>` | 按内容哈希保存的技能文件（删除专家不回收） |
| `imports/` | 待确认的导入，24 小时后清理 |
| `.trash/` | 覆盖、删除前的 `catalog.json` / `tools.json` / `builtin-scenarios.json` 备份与删除的专家记录 |

停服后备份整个 `experts/` 目录即可完整恢复；需要回退某次误操作时，从 `.trash/` 取对应时间的备份替换回原位置后重启。

## 排查

- **某人看不到专家**：按他的工号请求公开目录核对（`curl -s -H "X-Ops-Employee-Id: <工号>" <官网>/api/experts/v1/catalog`）；
  确认专家已发布、已上架、工号在名单里（不区分大小写）。不可见的一切请求都返回 404，不暴露专家是否存在。
- **工作助手提示目录暂不可用**：公开接口只接受工作助手后端的请求，带浏览器 `Origin` 的请求返回 403；按来源地址每分钟最多 600 次，超出返回 429。
- **技能被拒**：导入时以“技能「x」：原因”列出，手动上传为 `INVALID_EXPERT_SKILL`；原因直接写明规则与上限，例如“有 2001 个文件，
  超过 2000 个上限”“SKILL.md 的 name（a）与技能名称（b）不一致”“压缩包里找不到技能的 SKILL.md”。规则与工作助手「我的技能」导入一致，
  请创建者在工作助手里改好后重新导出。
- **导入被拒**：错误码 `INVALID_EXPERT_PACKAGE`（文件损坏、未登记文件、清单与内容不符、工具定义带密钥或本机路径）、
  `EXPERT_PACKAGE_REJECTED`（指标库不存在、未知内置工具、同名工具未选择处理方式）；页面会逐条列出原因。
- **工具库改不了**：`INVALID_EXPERT_TOOL` 表示改后的地址或命令不符合可移植规则（例如地址里带 `token=` 参数、命令是本机路径）；
  `EXPERT_TOOL_IN_USE` 会列出仍在引用的专家。
- **场景没出现**：新版工作助手请求目录时带 `X-Ops-Expert-Features: scenarios`，只有这样才会收到 `experts[].scenarios` 与
  `builtinScenarios`：`curl -s -H "X-Ops-Employee-Id: <工号>" -H "X-Ops-Expert-Features: scenarios" <官网>/api/experts/v1/catalog`。
  不带这个请求头时目录里没有这两个字段，有场景的专家其 `starterPrompts` 为场景名称。云端专家的场景需要“发布新版本”；内置专家场景需要在页签里“发布”。
- **导入报“未知字段 scenarios”**：官网仍是契约 0.1.0，按“升级顺序”先升级官网再导入；导出方无需重新导出。
- **场景保存被拒**：`INVALID_EXPERT`（云端专家）或 `INVALID_SCENARIOS`（内置专家）会逐条写明“常用场景第 N 个”的问题，例如名称超长、
  `【】` 超过 3 处、模板里疑似带了令牌。`BUILTIN_EXPERT_NOT_FOUND` 表示请求的不是五位内置专家之一。
- **`builtin-scenarios.json` 损坏**：带场景特性的目录请求返回 503，旧客户端不受影响；从 `.trash/` 取最近的备份替换回原位置即可。
- 工号只用于筛选与判断可见，不写入普通日志。
